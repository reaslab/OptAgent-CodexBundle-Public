# 用户可读的数学报告

每个实际采用的模型在首次编写建模或求解代码前，都先有一份简短 Markdown 数学说明，并按 `opt-workflow` 展示；数学语义实质变化时先更新并展示，再改模型代码。已有模型先读取核对，补写或更新说明并展示后再修改或求解。说明应列出变量与定义域、目标方向和单位、定义模型所需的全部约束族及索引/量词、必要符号和假设，可紧凑合并但不能省略必要关系。这份说明也适用于纯代码任务和 LaTeX/PDF 任务，不等于完整报告。用户明确只要求代码时，交付可见代码和该模型说明，不额外生成完整报告。需要撰写完整数学或业务报告时，先读取并遵循[共同写作规范](../opt-writing/SKILL.md)；模型叙述、数学表达、结果解释、派生指标和行文结构只在该 skill 维护。

## 格式与位置

- 短稿默认保存在当前 Case 实际 `artifact_dir/model.md`；若用户已有同用途模型说明，更新并展示其真实路径，不再复制一份。仅模型说明作为成品时，可用该文件作为 Review 的 `report_path`。
- 需要完整最终报告且用户未指定格式时默认生成 Markdown；默认 Markdown 报告保存在实际 `artifact_dir/report.md`，复用并展开短稿中的数学内容。当前请求中的明确格式优先，未要求完整报告时不额外生成。报告须自足，不能只链接到 `model.md`。用户明确只要求代码时，无需另写完整报告。
- 用户要求 LaTeX 源、论文排版或 PDF 时，按 `opt-writing` 使用相应语言模板。LaTeX 项目放在实际 `artifact_dir/paper/`，已有内容增量编辑，不重置用户目录。`paper/main.pdf` 是唯一审查与交付主成品；`.tex`、section、图表及运行依赖作为配套源码。不把 `main.tex` 当作完整报告。
- 用户本次同时要求 Markdown 与 PDF 时，选定一个主成品绑定 Review，再由主稿派生副格式；在终稿复读阶段对照两份的题意、假设、模型、方法、结果、单位、结论范围和限制，不另起一套写作或双格式审批状态。
- model.md 与完整报告遵循本次请求指定的语言；未指定时按题目材料和用户交流语言决定。不得从 Case ID 推造文件夹路径，使用 Core 返回的实际 artifact_dir。

## 证据与协作

- 报告中的数值、结论和来源范围应与当前绑定的 Source、Candidate、Run、Result/Seal 及有效 Review 一致；数学 claim 的核对、反馈、最终成品读取和批准均遵循[opt-review](../opt-review/SKILL.md)。正文写作不能替代 Verifier 的独立来源核验。
- Review 的开工、终稿交接与等待顺序见 `opt-review`，本 skill 不重复定义。
- Review ready 后不得改写其绑定的主成品。用户要求扩写或更新时，按 `opt-review` 的 linked Review 分支重新核读新增成品并绑定新字节；不沿用旧文件的批准状态。
- Case README 默认使用 Core 根据实际导出闭包生成的运行说明；闭包生成前不要预写入口、输入或依赖路径。若 Core 保留了用户已有 README，按工具返回的实际路径检查；需要补充运行信息且该 README 不属于已审主成品时再补，不改动已审主成品。内部审查流转和诊断细节留在系统记录，不写入面向用户的报告。

## 构建与交付

- LaTeX/PDF 按 `opt-writing` 的本机编译步骤构建。确认本次生成的 PDF 存在且可读取后，才将它作为最终成品。
- 用户要求 PDF 时，Verifier 必须按 `opt-review` 全文读取最终 PDF。构建成功、PDF 字节绑定和全文可读是不同事实。
- README 应说明与用户实际运行相关的依赖；不把临时诊断文件塞进交付目录。
- 用户明确请求选择证据摘要时，才调用 `optagent.deliver_build` 写入所指定的新路径。数值交付须根据 ready Review 明确批准的证据调用 `optagent.deliver` 的 `select`，不要自动选择。用户明确要求可复现 ZIP 时，基于该 Delivery 调用 `optagent.deliver` 的 `package` 正式打包，并提供已批准成品和 ZIP 的实际路径；只对已实际验证的复跑范围承诺可复跑。范围限当前 Case 和所选材料，不含凭证、其他 Case 或缓存。

过程和最终对话都以用户可用的信息说明结果与进度、必要的下一步、重要限制和实际文件路径；仅在解释具体问题确需定位时使用内部状态或工具名称。成品的内容标准见 `opt-writing`；Review 与证据选择标准见 `opt-review`。
